## 🚀 SpecKit 기반 명세 주도 개발(SDD) 마스터 

---

### [Part 1: 초급] SpecKit 핵심 구조와 SDD 워크플로우 (1강 ~ 10강)
단순한 '바이브 코딩(Vibe Coding)'의 한계를 넘어, 문서 중심의 체계적인 AI 개발 프로세스를 확립하는 단계입니다.

* [**1강: Spec-Driven Development(SDD)의 이해**](./01-SDD의-이해/01-SDD의-이해.md): AI 에이전트의 환각(Hallucination) 현상을 제어하는 명세 주도 개발 패러다임과 SpecKit의 역할
* [**2강: 개발 환경 셋업**](./02-개발-환경-셋업/02-개발-환경-셋업.md): Mac 환경에서 Python 패키지 관리자(uv) 및 `specify-cli` 설치, AI 에이전트와 SpecKit 연동하기
* [**3강: 코어 폴더 구조 파헤치기**](./03-코어-폴더-구조-파헤치기/03-코어-폴더-구조-파헤치기.md): `.specify` 내의 `memory`, `templates`와 산출물이 저장되는 `specs` 폴더 구조 이해
* [**4강: 프로젝트 불변 원칙 수립 (`/speckit.constitution`)**](./04-프로젝트-불변-원칙-수립/04-프로젝트-불변-원칙-수립.md): 기술 스택, 시큐어 코딩 기준, 프론트엔드 컨벤션 등 AI가 절대적으로 지켜야 할 규칙 정의
* [**5강: 비즈니스 요구사항 명세 (`/speckit.specify`)**](./05-비즈니스-요구사항-명세/05-비즈니스-요구사항-명세.md): 기술적인 구현(How)을 배제하고 '무엇을(What)', '왜(Why)' 만드는지에 집중한 `spec.md` 작성 가이드
* [**6강: 요구사항 구체화 (`/speckit.clarify`)**](./06-요구사항-구체화/06-요구사항-구체화.md): AI가 먼저 던지는 질문에 답변하며 기획의 모호성을 제거하고 명세서 완성도 높이기
* [**7강: 기술적 구현 계획 수립 (`/speckit.plan`)**](./07-기술적-구현-계획-수립/07-기술적-구현-계획-수립.md): 아키텍처, 폴더 구조, `data-model.md` 및 `research.md` 자동 생성 프로세스
* [**8강: 액션 가능한 작업 분할 (`/speckit.tasks`)**](./08-액션-가능한-작업-분할/08-액션-가능한-작업-분할.md): 구현 계획을 기반으로 상세 체크리스트(`tasks.md`) 추출하기
* [**9강: AI 기반 코드 구현 (`/speckit.implement`)**](./09-AI-기반-코드-구현/09-AI-기반-코드-구현.md): 태스크 목록을 순차적으로 실행하며 실제 코드가 생성되는 과정 통제
* [**10강: 리뷰 및 정합성 검증 (`/speckit.analyze`)**](./10-리뷰-및-정합성-검증/10-리뷰-및-정합성-검증.md): 생성된 코드가 초기 명세서 및 헌법(constitution)을 완벽히 준수했는지 교차 검증하기

### [Part 2: 고급] 실제 개발 Lifecycle 적용 및 고급 설정 (11강 ~ 20강)
보안, 아키텍처, 협업 룰을 템플릿에 주입하고, 실제 프로덕션 레벨의 라이프사이클에 SpecKit을 최적화하는 단계입니다.

* [**11강: 애자일(Agile) 워크플로우에 SpecKit 통합하기**](./11-애자일-워크플로우에-SpecKit-통합하기/11-애자일-워크플로우에-SpecKit-통합하기.md): 티켓 단위의 작업부터 명세, 구현까지 이어지는 반복 스프린트 구축
* [**12강: 커스텀 템플릿(Templates) 고도화**](./12-커스텀-템플릿-고도화/12-커스텀-템플릿-고도화.md): 팀의 기술 스택(예: Spring Framework 등)과 구조에 맞춘 SpecKit 템플릿 개조 및 배포
* [**13강: 팀 단위 협업 전략**](./13-팀-단위-협업-전략/13-팀-단위-협업-전략.md): 기능별 Git 브랜치 생성 및 순차적 Spec 파일 번호(예: `001-feature`) 관리를 통한 형상 충돌 방지
* [**14강: OpenAPI 명세서 연동**](./14-OpenAPI-명세서-연동/14-OpenAPI-명세서-연동.md): `contracts/api.md` 생성을 통한 RESTful API 엔드포인트의 일관성 및 명확한 통제
* [**15강: Constitution 기반 강력한 보안 정책 주입**](./15-Constitution-기반-강력한-보안-정책-주입/15-Constitution-기반-강력한-보안-정책-주입.md): 민감 데이터 처리 원칙 및 보안 가이드라인을 AI에게 강제하는 노하우
* [**16강: 기존 프로젝트(Brownfield)에 SpecKit 도입**](./16-기존-프로젝트에-SpecKit-도입/16-기존-프로젝트에-SpecKit-도입.md): 레거시 코드베이스의 컨텍스트를 유지하며 신규 기능 안전하게 확장하기
* [**17강: 테스트 주도 개발(TDD) 결합 워크플로우**](./17-테스트-주도-개발-결합-워크플로우/17-테스트-주도-개발-결합-워크플로우.md): 로직 구현 전, 테스트 코드를 먼저 작성하도록 `tasks.md`의 우선순위 강제하기
* [**18강: 대규모 개발 시 컨텍스트 관리**](./18-대규모-개발-시-컨텍스트-관리/18-대규모-개발-시-컨텍스트-관리.md): 도메인별 기능 분할을 통해 LLM의 기억력 상실(Context Limit) 한계 극복 테크닉
* [**19강: CI/CD 파이프라인 정합성 검토**](./19-CI-CD-파이프라인-정합성-검토/19-CI-CD-파이프라인-정합성-검토.md): 코드 리뷰 단계에서 SpecKit 산출물 기반의 체크리스트 자동 검증 파이프라인 구상
* [**20강: 1인 AI 비즈니스 창업을 위한 초고속 사이클 완성**](./20-1인-AI-비즈니스-창업을-위한-초고속-사이클-완성/20-1인-AI-비즈니스-창업을-위한-초고속-사이클-완성.md): 기획-명세-구현-배포까지 시간을 획기적으로 단축하는 마스터 워크플로우 구축

### [Part 3: 실전] SpecKit 활용 실무 프로젝트 구축 (21강 ~ 23강)
수립된 기준과 명령어를 활용하여, 프론트엔드 통합과 데이터 관리가 필수적인 실무 시스템을 단계별로 구축합니다.

[**21강: 쇼핑몰 데이터베이스 설계**](./21-쇼핑몰-데이터베이스-설계/21-쇼핑몰-데이터베이스-설계.md)
* `/specify`: 쇼핑몰 핵심 도메인(상품, 장바구니, 주문, 결제) 요구사항 명시
* `/plan`: `data-model.md`를 생성하여 ERD를 대체할 마크다운 기반 스키마 설계
* **데이터베이스 최적화:** `constitution.md`에 MySQL, MongoDB 등 타겟 DB 제약조건을 명시하여 AI가 정확한 마이그레이션 코드를 짜도록 유도

[**22강: 로그인 RBAC 기반 인증/권한 시스템 개발**](./22-로그인-RBAC기반-인증-권한-시스템-개발/22-로그인-RBAC기반-인증-권한-시스템-개발.md)
* `/specify`: 관리자(Admin), 일반(User) 등 역할(Role) 정의 및 자원 접근 제어 정책 작성
* **보안 아키텍처 적용:** JWT 등 인가 모델의 보안 요구사항을 `research.md`와 `plan.md`에 반영
* `/implement`: 권한에 따른 라우터 접근 차단 미들웨어 및 서버사이드 필터링 로직 구현 통제

**23강: 메뉴 관리 시스템 개발**
* **트리(Tree) 구조 데이터 처리:** 무한 뎁스 계층형 메뉴 관리를 위한 데이터 구조 명세화
* `/tasks` 세분화: 백엔드 계층형 응답 API 개발과 프론트엔드 동적 메뉴 렌더링 작업 단위 분리
* **통합 및 검증:** 22강의 RBAC 권한 시스템과 결합하여 로그인한 사용자 역할에 따라 동적으로 노출 메뉴가 달라지도록 개발 후 `/analyze`로 무결성 검증
