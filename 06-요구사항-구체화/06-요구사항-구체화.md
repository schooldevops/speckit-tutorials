# 6강: 요구사항 구체화 (/speckit.clarify)

## 개요
초기 기획서(`spec.md`)의 모호성을 제거하기 위해, AI가 역으로 질문을 던져 구멍(Edge Case)을 채우는 과정입니다.

## 학습목표
- 기획 모호성 발견 원론 이해
- 역질문 티키타카를 통한 명세 고도화
- 엣지 케이스 방어책 마련

## 사용형식 / 메뉴얼

```mermaid
flowchart LR
    A[초기 spec.md] --> B(AI: 모호성 질문)
    B --> C[개발자 피드백]
    C --> D[구체화된 spec.md 완성]
```

## 직접해보기

**Step 1. 구체화 촉발**
명령어 `/speckit.clarify`를 실행하고 AI에게 "구체화를 위해 질문해줘"라고 지시합니다.

**Step 2. 답변 및 합의**
AI의 "장바구니 동일 상품 추가 시 분기 처리?" 같은 날카로운 질문에 인간의 언어로 답장합니다.
AI가 대화를 바탕으로 명세서를 업데이트합니다.

## 실전 예제

**예제 1. 모호성 검증 프롬프트 투입**
`specify clarify` 명령어를 사용하여 AI가 기획서의 빈틈을 찾도록 지시합니다.
```bash
specify clarify --spec specs/spec.md
```

**예제 2. 구체화 로그 파일 관리**
AI와의 질의응답 내역을 파일로 저장하여 기획 히스토리를 남깁니다.
```bash
specify clarify --spec specs/spec.md --export specs/clarify-log.md
```

**예제 3. 엣지 케이스만 집중 도출**
명령줄 인자를 통해 '보안'과 '오류 상황'이라는 특정 엣지 케이스만 공격적으로 묻게 합니다.
```bash
specify clarify --focus "Edge cases and Error handling"
```

## Tips 
- **주의사항**: 질문에 답하기 귀찮다고 넘기면 버그로 직결됩니다.
- **다이나믹한 활용법**: "고객 센터 클레임이 가장 많을만한 에러 상황도 질문해줘" 처럼 예외 상황을 집중 유도하세요.
